# Product UX Principles

## Fast comprehension

A frequent screen should expose current state, required action, exceptions, relevant history, and next step.

## Density by role

Use high density for positions, trades, ledger entries, risk, performance comparisons, and review queues.

Use more space for complex planning, reflective review, destructive confirmation, first-time setup, and error recovery.

## Forms

- Group by decision, not database table.
- Keep labels short.
- Put units beside values.
- Show computed outputs live.
- Distinguish required, recommended, and optional inputs.
- Preserve pre-trade evidence from post-trade edits.
- Avoid making prose mandatory unless it serves the process.

## Navigation

Primary navigation should reflect user jobs: monitor, plan, record, review, analyze, and reconcile.

Avoid navigation based solely on internal data models.

## Tables

Prioritize high-value columns, right-align numbers, use tabular numerals, keep rows compact, make row actions predictable, and preserve useful sorting/filtering state.
